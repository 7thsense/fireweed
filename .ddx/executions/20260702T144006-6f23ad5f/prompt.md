    <title>Add public hot projection query types and capability flags</title>
    <description>
PROBLEM&#xA;The public Rust facade only exposes exact item reads and exact index lookups. The hot projection contract needs typed query request/response shapes before backend work can be implemented consistently.&#xA;&#xA;PROPOSED FIX&#xA;Add domain-neutral query model types for filters, typed values, range bounds, sort keys, cursor page requests/responses, aggregate/grouping requests, numeric buckets, bounded mutation requests, and advertised capability flags. Wire the public facade surface as compile-tested stubs that return `EngineError::Unavailable` until backend beads implement support.&#xA;&#xA;IN-SCOPE FILES&#xA;- crates/pqueue-core/src/domain.rs or a focused query module for public data types.&#xA;- crates/pqueue-engine/src/port.rs for capability/query traits.&#xA;- crates/pqueue/src/lib.rs for facade methods that expose the new types.&#xA;&#xA;OUT-OF-SCOPE&#xA;- Memory/sqlite query execution.&#xA;- Snorri-specific names or policies.&#xA;- Aggregation implementation beyond type definitions and unsupported defaults.&#xA;&#xA;CAPABILITY FLAGS&#xA;Advertise at minimum: range_scan, grouped_aggregates, numeric_buckets, bounded_mutation, claim_by_query, side_record_query. In this epic `side_record_query` is defined but never implemented — every backend advertises it unavailable (see the epic and contract).

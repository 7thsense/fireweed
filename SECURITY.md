# Security policy

## Report a vulnerability privately

Do not disclose a suspected vulnerability, exploit, secret, or sensitive log in
a public issue or discussion. Use GitHub's private vulnerability reporting
form: open this repository's **Security** tab, select **Advisories**, then
**Report a vulnerability**.

Include, when available:

- the affected Fireweed Queue version or commit;
- the affected configuration or storage backend;
- impact and prerequisites;
- minimal reproduction steps; and
- suggested mitigations or disclosure constraints.

Remove credentials, personal data, and unrelated customer data. If GitHub does
not offer the private reporting form for this repository, do not post the
details publicly. There is no alternate public reporting channel; wait for the
repository to publish a private contact method.

## Response and disclosure

Maintainers review security reports on a best-effort basis. The project does
not promise an acknowledgement, fix, release, or disclosure timeline. Please
allow maintainers to assess the report and coordinate disclosure before making
details public. Submitting a report does not create a bounty, payment, or
support obligation.

Only versions identified as supported in published release documentation are
eligible for security fixes. A report against another version is still useful,
but maintainers may address it only in a newer release.

Ordinary bugs, usage questions, documentation problems, and compatibility
reports belong in public issues; see [SUPPORT.md](SUPPORT.md).

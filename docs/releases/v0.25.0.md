# Fireweed Queue v0.25.0 public preview

v0.25.0 is a **source release** focused on Snorri integration regressions from
v0.24.0, external-trigger claim-by-identity, RESP stock binding, and facade
verification. It does **not** complete the native-async bridge removal epic
(process-wide `BlockingLibBackend` remains for most matrix cells).

## Highlights

- **Snorri async regressions fixed** — eligibility index no longer duplicates
  item ids after re-`create_queue` / recovery; `AsyncLogReplayBackend` restores
  `claim_by_query`, `batch_update`, and `bounded_mutation` with capability ads
  that match behavior; object-log open is safe on current-thread Tokio runtimes
  (no `block_in_place` panic).
- **BatchClaimByItemIds** — API-001 / Rust `claim_by_item_ids` leases a
  caller-supplied `item_id` set with partial per-id outcomes and ordinary lease
  lifecycle (inspect, timeout/reclaim, force). Point lookup avoids full-shard
  eligible scans on the compose/memory path.
- **RESP `XCLAIM` first delivery** — pending eligible entry ids can be
  first-delivered without a prior `XREADGROUP >`. **Wire change:** stock Redis
  returns nothing for ids absent from the PEL; fireweed now first-delivers
  base-eligible pending ids and charges one attempt. Clients that probe with
  `XCLAIM` will trigger delivery. Self-renew and cross-consumer reassign
  dispositions are unchanged. If `claim_by_item_ids` is unavailable on a
  product, pending ids are omitted (not a whole-command failure).
- **Authoritative SQLite log PRAGMAs** — `SqliteLog` sets `journal_mode=WAL`,
  `synchronous=FULL`, and `busy_timeout` (TD-005 residual).
- **Facade verification** — `cargo test -p fireweed --lib` is wired into
  release and fast-functional gates; incomplete LogEngine facade cases use
  explicit `#[ignore]` reasons.
- **Native-async product direction** — API-005 documents one concrete async
  `Fireweed` end-state; matrix inventory records which cells still use the
  process-wide blocking bridge.

## Breaking / migration notes

- No intentional on-disk format break beyond v0.24.0's object-log LogEngine
  cutover (already documented there).
- Embedders depending on missing async query ports in v0.24.0 should repin to
  v0.25.0 for `claim_by_query` / `batch_update` / `bounded_mutation` and for
  `claim_by_item_ids` / RESP `XCLAIM` first delivery.
- Relational sqlite/postgres may still advertise `claim_by_item_ids: false`
  until a follow-on lands; compose/memory (and products over that path) implement it.
- Process-wide `BlockingLibBackend` remains the product open path for most
  storage cells; removing it is tracked under epic `fireweed-0a103d61`.

# Fireweed Queue v0.26.0 public preview

v0.26.0 closes the Snorri validation gaps found against v0.25.0 and removes the
process-wide `BlockingLibBackend` product open path for the public matrix
(adapter-local offload remains where substrates are still sync).

## Highlights

### Snorri integration (v0.25 validation)

- **Compatibility claims** — `claim_with` / `metadata_equals` / `group_key`
  filters work on memory async projections (and sqlite paths that use them).
- **Push request-id across reopen** — empty and non-empty request-id batches
  retain conflict/replay semantics after sqlite async reopen (including empty
  workflow enqueue).
- **Object-log Strict barrier** — default `ResponseBarrier::Strict` advertises
  and implements atomic transition commit capabilities on LogEngine products
  (Snorri CONTRACT-003).

### Native-async product path

- **No process-wide BlockingLibBackend on product opens** for memory, sqlite,
  postgres, and object-log matrix cells. Durable I/O uses adapter-private
  offload (`BoundedBlockingExecutor` / axis offload) where substrates are sync.
- **memory×memory** remains pure ready-future async composition.
- **object-log** ports run on the existing process-wide LogEngine multi-thread
  runtime without wrapping every facade op in BLB.
- Concurrency model: per-queue serialization remains for correctness; cross-queue
  progress is required. Snorri should **repin to v0.26.0**.

## Verification

- `cargo test -p fireweed --lib` (public_open_* + facade suite)
- `cargo test -p fireweed-engine --lib`
- `cargo test -p fireweed-objectlog --lib`
- `cargo test -p fireweed-sqlite --lib` / eligibility recovery
- `cargo test -p fireweed-engine --test claim_by_item_ids`
- Env-gated postgres: `FIREWEED_PG_TEST_URL=… cargo test -p fireweed --features postgres --lib public_open_postgres`

## Residual

- Adapter-local offload is still present for rusqlite / sync postgres client —
  not pure non-blocking under poll on every axis. End-state native async drivers
  remain future work.
- Object-log LogEngine product still has incomplete ports (upsert / update_fields /
  etc.) documented via `#[ignore]` facade tests.
- Governed 10M / TP-002 evidence track remains separate.

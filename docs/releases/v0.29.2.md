# Fireweed Queue v0.29.2 public preview

v0.29.2 closes the remaining Snorri objectlog recovery gaps found after v0.29.1:
reopen-safe LogEngine data object ids, and ItemMutationPort on hybrid Strict.

## Highlights

### object-log reopen counter (fireweed-481d3e43)

- Depend on **object-log v0.3.1** (git tag): LogEngine resumes the data-object
  counter past existing keys under the data prefix after process restart.
- Without this, reopen overwrote sealed objects while manifests still pointed at
  old byte ranges → `RangeOutOfBounds` / mid-JSON EOF (~19KiB frames) during
  checkpoint catch-up.
- Regression: `local_log_reopen_preserves_large_batches_across_process_boundary`.

### ItemMutationPort on hybrid Strict (fireweed-c62067d2)

- `open_objectlog_sqlite` (hybrid) implements `mutate_items`: plan + MutateItems
  append under `submit_operation`, with durable request-id replay.
- Unblocks Snorri membership replace and live-mutation objectlog tests that
  previously failed closed with `Unavailable`.

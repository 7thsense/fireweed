# Fireweed Queue v0.27.0 public preview

v0.27.0 closes Snorri correctness and objectlog surface gaps found against
v0.26.0, plus FWSG→LogEngine open-time generation detection for operators.

## Highlights

### Correctness

- **Fenced side records under concurrent commits** — async `commit_transition`
  holds the per-queue gate across fence validation and side-record apply, so
  racing same-instance commits no longer last-writer-wins past a failed fence
  (fireweed-5497780d).
- **Push request-id fingerprints on recovery** — missing envelope fingerprints
  are recomputed from durable Push bodies so changed-body replay after sqlite
  reopen returns `RequestIdConflict` (fireweed-6486ed63). Empty batches still
  enter the ledger when a `request_id` is present.

### Object-log product surface

- **AsyncComposed objectlog ports** — upsert, commit_transition (+ side
  records), batch_update, hot projection query (`range_scan`, aggregates,
  `claim_by_query`, `claim_by_item_ids`), and index query on memory / sqlite /
  hybrid LogEngine products (fireweed-dd6cbcde). Strict path remains the
  atomic-capable surface.

### Storage generation

- **FWSG open fail-closed** — opening retired segmented FWSG layout returns a
  detectable `EngineError::Storage` with
  `INCOMPATIBLE_OBJECT_LOG_GENERATION` / `MIXED_OBJECT_LOG_GENERATION` tokens
  and operator migration docs (fireweed-24c1767f).

## Residual

- Exact 10M E3 snapshot-tail recovery evidence and broader post-v0.15 TP-002
  release-tier gate work remain open (`fireweed-3aaa3ebc`, epic
  `pqueue-c4e5f691`).
- Some LogEngine facade paths remain incomplete (item mutation, historical
  as-of reads) and stay `#[ignore]` or `Unavailable` where not implemented.

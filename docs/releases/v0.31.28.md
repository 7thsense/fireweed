# Fireweed v0.31.28 — storage cleanup and correctness

This is a source-preview release, published as a prerelease. It does not claim
product-ready P20pr deployment qualification. The archive, workspace-package
SBOM, unsigned source provenance and checksums identify the measured source;
the release tag identifies the subsequent evidence commit.

The supported storage matrix is four logs (memory, PostgreSQL, filesystem, S3)
by three projections (memory, Turso, PostgreSQL). Retired SQLite implementations,
disabled test paths, duplicated migration tests and unused dependencies are
removed. Useful behavioral tests use the current native Turso implementation.
Compatible dependencies and the site browser-test dependency are refreshed.

Correctness fixes cover sparse log-tail recovery, PostgreSQL claim persistence,
compact-entity mutation planning, retained-row forwarding, Turso row versions
and serialized ID/key batch updates, and lease renewal after asynchronous
claims. The log remains the sole durability authority. Projections remain
reconstructible; workflow enrichment stays on each original row.

Whole-cohort claims now persist their bearer tokens atomically with the lease.
If an older Turso projection already has an active cohort lease with a missing
bearer, rebuild that disposable projection from its authoritative durable log
before resuming workers. Ordinary catch-up skips already-applied commands and
does not repair this prior state. Preserve the log and its request history.

Native Turso now implements discovery, exact and typed index queries, range and
aggregate queries, query claims, gates, scalar rescheduling, selector mutations,
and full logged transitions across the supported log compositions. Query claims
retain receipts through reopen; complete mutations validate before append. The
ordinary unindexed enrichment path retains its bounded generation implementation.
The optional projection-maintenance handle and universally deferred
`side_record_query` capability remain outside this parity surface.

See [maintenance verification and performance](https://github.com/7thsense/fireweed/blob/v0.31.28/docs/perf/maintenance-release-baseline.md)
for test results, measured source identity, current workflow capacity and hardware
arithmetic. The baseline distinguishes complete recipient workflows from primitive
row-operation throughput. Source-candidate verification and fresh repeated
measurements must complete before publication; the evidence commit records them.

## Identity policy

The pre-S reserved identity is `v0.31.28`; synchronized workspace packages use
`0.31.28`. Helm source defaults, the independent benchmark tool and gate-set
versions retain their independent coordinates. The live `.ddx` tracker is not
product authority. Before tagging:

```sh
bash scripts/release/list-public-version-sources.sh v0.31.28
bash scripts/release/verify-release-identity.sh --version 0.31.28
```

An explicit source-preview manifest selects the prerelease packaging route.
Releases without that manifest retain the governed deployment gates. This is
not a signed supply-chain or remote-log throughput claim.

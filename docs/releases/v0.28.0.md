# Fireweed Queue v0.28.0 public preview

v0.28.0 lands the LogEngine E3 recovery product path and the log-pagination
fix required for exact multi-million genesis replay, with live MinIO
evidence for both snapshot-tail and genesis 10M recovery contracts.

## Highlights

### Object-log recovery (LogEngine)

- **E3 harness on LogEngine products** — TP-002 E3 live tests open
  `ObjectLogEngineStore::open_s3` with `AsyncObjectLogMemoryBackend`
  (genesis) and `AsyncObjectLogSqliteBackend` (snapshot high-water + tail)
  instead of retired FWSG facades (fireweed-3aaa3ebc).
- **RecoveryStats on product open** — `start_seq`, `tail_replayed`,
  `snapshot_used`, and page/resource counters are recorded for recovery
  contracts and operator diagnostics.
- **Crash-tail fault model** — SQLite crash tail uses
  `RawCommitFault::AfterAppendBeforeApply` (append durable, apply suppressed).

### Correctness

- **Non-truncating `read_from` pages** — `ObjectLogEngineStore::read_from`
  always returns a next cursor on non-empty pages so a 4 MiB fetch that
  yields fewer than `limit` entries cannot stop multi-million genesis
  recovery early (fireweed-3aaa3ebc / genesis short-count fix).

### Perf tooling

- **E3 script TP-003 seed fallback** — `scripts/perf/tp002-e3-s3.sh` seeds
  transaction evidence from governed `docs/perf` TP-003 JSONL when the
  retired FWSG matrix test binary is absent.

## Headline

The shared SQL apply hop from v0.31.18 no longer parks the object-log
runtime. Turso RelTx work runs on `spawn_blocking` with a thread-local
runtime, Push group summaries use in-memory item refs, and the apply-start
delay is per-shard on the first produce batch.

## Cut contents

- Turso `run_reltx_blocking` replaces `block_in_place`. RelTx statements
  `block_on` a thread-local current-thread runtime instead of borrowing the
  object-log / SS test runtime (2 worker threads).
- `apply_owned` clones the Turso transaction into that blocking hop and
  writes persist maps back after it returns.
- Push group-summary rows are built from `PushItem` (`group_item_refs_from_specs`);
  apply no longer `SELECT`s the rows it just inserted (`load_grouped_items`).
- `insert_item_specs` returns the allocated `base_seq` so those refs have
  stable FIFO positions.
- `Coordinator::new` preserves `apply_start_delay_ms`. The delay runs once
  per shard on the first Push/UpdateFields hop, not as a worker-start sleep
  that warmup can burn.
- Probe: a Turso reader `SELECT` does not wait on a held `IMMEDIATE` writer.

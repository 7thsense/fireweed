# Fireweed Queue v0.29.1 public preview

v0.29.1 closes the residual Snorri objectlog claim→commit lease window that
survived v0.29.0: hybrid Strict products no longer drop lease cleartext when
adapters re-call `create_queue` between claim and commit.

## Highlights

### Correctness (Snorri / fireweed-2ad3a030)

- **`claim_by_query` under queue gate** — prepare + append/apply for
  `claim_by_query` now run under `submit_operation` on memory, sqlite, and
  hybrid objectlog products (parity with `claim_by_item_ids`).
- **Hybrid lease cleartext across `create_queue`** — `HybridProjectionStore::ensure_shard`
  no longer re-exports SQLite into hot memory when the shard is already
  hydrated. SQLite stores only `lease_token_hash`; rehydrate wiped process-local
  cleartext and made the next `commit_transition` report `StaleLease` even though
  the item remained `Leased`.
- **Export overlay** — projection image export fills lease tokens from the
  process-local live token map so recovery images retain claim authority.
- **Hybrid catalog + counters** — `create_queue` registers durable definitions
  into the object-log catalog (parity with memory/sqlite products) and open-time
  recovery seeds `QueueCounters` past durable item ids.
- **Regressions** — objectlog sqlite `claim_by_query_then_immediate_commit_transition_succeeds`;
  facade `public_open_objectlog_sqlite_claim_by_query_then_commit` (including a
  second `create_queue` between claim and commit).

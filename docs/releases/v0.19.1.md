# pqueue v0.19.1

## Admission ordering fix

- The async object-log executor now releases a completed operation's shared-capacity slot before publishing
  its reply. A caller that immediately submits follow-up work no longer receives a transient
  `Unavailable` after the prior operation has already reported success.
- Accepted work remains owned by the executor when its caller future is dropped, and queue-local FIFO
  serialization is unchanged.

## Included v0.19 release changes

- Runtime-neutral async storage contracts cover complete queue lifecycles across the memory, SQLite,
  PostgreSQL, object-log, composed, and feature-gated Turso paths.
- Multi-claim continuations commit atomically, explicit eligibility-time claims are supported, and filtered
  lifecycle metrics recover consistently across supported backends.
- E2 cross-queue scale/density and E3 object-log load evidence always run in the release workflow. Portable
  gates use same-run comparisons, bounded degradation, progress, batching, and exact recovery. No active
  quiet-host deferral path remains.
- Absolute throughput and latency remain reported as deployment-capacity evidence only when topology and
  resource limits are declared.

## Verification

- The cancellation-after-acceptance regression passed 100 consecutive focused runs.
- The complete object-log library suite and warning-denied object-log Clippy passed.

  are required again for this corrected tag.

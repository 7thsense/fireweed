# pqueue v0.18.0

## Full-async storage and Turso projection

- Storage ports now expose runtime-neutral async boundaries, with bounded Tokio dispatch, keyed object-log
  execution, ordered group commit, ownership fencing, recovery, and complete push/claim/lease/finalize/
  reclaim/control lifecycle paths.
- A feature-gated, Rust-native Turso projection adapter implements typed indexes, grouped cohorts, queue
  controls, mutation parity, reclaim selection, and replay alongside SQLite and Postgres.
- Driver-neutral relational codecs, rows, schemas, and SQL construction are shared instead of duplicated
  across relational adapters.

## Object-log durability and operations

- Global byte admission bounds retained records and seal-frame copies before coordinator registration;
  oversized batches fail before permits or dispatch, and valid batches roll over by sealing an existing
  prefix first.
- Deterministic storage simulation covers object-store faults and sequenced metadata protocols. Metadata
  publication is fenced and ordered across authority, retention, and maintenance boundaries.
- Object-store observability distinguishes physical operations from logical validation and records exact
  attempts and transferred bytes without exposing object keys or error text.
- Maintenance work is resumable and bounded by explicit page, request, and work budgets. Content-addressed
  CAS loser cleanup preserves shared winning objects while reclaiming distinct losing objects.
- Ownership-handoff profiling found repeatable request savings but did not meet the governed 20% relative
  improvement bar, so this release does not add speculative warmup or cache behavior.

## Versioned segment integrity

- Readers support arbitrarily interleaved v2 and v3 segments. V3 adds per-record Castagnoli CRC32C, a
  full-frame CRC32C, complete-object SHA-256 identity, explicit manifest entry kinds, typed/redacted
  corruption stages, bounded two-pass decoding, and canonical same-queue locator validation before GET.
- Release 0.18.0 keeps the v2 writer default. Operators may opt into v3 with
  `PQUEUE_SEGMENT_WRITER_FORMAT=v3`; committed v3 objects require 0.18.0-or-newer readers until they age out.
- New frames are capped at 64 MiB, individual canonical records at 16 MiB, and record counts at 1,000,000.
  Historical pre-release v2 objects above those governed limits require explicit migration before rollout.

## Release boundary

- Niflheim remained in service. Quiet-host E2 density and governed release-tier E3 cost/recovery measurements
  are explicitly deferred for v0.18.0; shared GitHub runners do not execute those scaled workloads.
- The release gate still requires host-independent correctness evidence, E3 smoke rows, coverage, build
  closure, Helm validation, packaging, and the four-combination kind storage matrix.
- The ignored v2/v3 encode/decode/mixed-replay harness remains manual and was not used to make a timing claim.
- The workspace MSRV remains Rust 1.92. V2 remains the default durable writer, so enabling v3 is the only
  action that changes the minimum reader version for retained object-log data.

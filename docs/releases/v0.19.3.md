# pqueue v0.19.3

## Deterministic reclaim-driver regression

- The background reclaim regression now advances Tokio's virtual clock instead of imposing a wall-clock
  scheduling budget on the host.
- The assertion observes the complete asynchronous outcome: both the reclaimed queue state and the
  subsequently published observability counter. It no longer races between those consecutive operations.
- Production reclaim behavior is unchanged; the test still proves that expired leases recover without
  client traffic and that the recovery is counted.

## Included v0.19 release changes

- PostgreSQL item claims explicitly restore priority/insertion order after atomic `UPDATE ... RETURNING`.
- The async object-log executor releases completed shared-capacity slots before publishing replies.
- E2 cross-queue scale/density and E3 object-log load evidence always run. Portable gates use same-run
  comparisons, bounded degradation, progress, batching, and exact recovery; no active quiet-host deferral
  path remains.

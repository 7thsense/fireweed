# pqueue v0.19.2

## Deterministic PostgreSQL claim ordering

- PostgreSQL item claims now restore queue order after the atomic `UPDATE ... RETURNING` operation.
  PostgreSQL does not define the row order produced by `RETURNING`; the claim now uses an ordered outer
  query keyed by the selected priority and creation sequence.
- The fix preserves `FOR UPDATE SKIP LOCKED`, atomic leasing, and the rich one-statement claim response.
- Claim responses now consistently follow the documented priority/insertion order across query plans and
  hosts.

## Included v0.19 release changes

- Runtime-neutral async storage contracts cover complete queue lifecycles across the memory, SQLite,
  PostgreSQL, object-log, composed, and feature-gated Turso paths.
- Multi-claim continuations commit atomically, explicit eligibility-time claims are supported, and filtered
  lifecycle metrics recover consistently across supported backends.
- The async object-log executor releases completed shared-capacity slots before publishing replies, so
  immediate follow-up work is not spuriously rejected.
- E2 cross-queue scale/density and E3 object-log load evidence always run in the release workflow. Portable
  gates use same-run comparisons, bounded degradation, progress, batching, and exact recovery; no active
  quiet-host deferral path remains.

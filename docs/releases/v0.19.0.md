# pqueue v0.19.0

## Async storage contracts

- Runtime-neutral async log, projection, and control-plane contracts now cover complete queue lifecycles,
  including cohorts, purge, maintenance, recovery, and cancellation after accepted work crosses an owned
  execution boundary.
- Composed backends defer storage work until futures are polled and serialize queue-local mutations without
  holding queue admission permits while group-commit callers wait for a seal acknowledgement.
- PostgreSQL, SQLite, object-log, memory, and server boundaries keep blocking storage work off Tokio reactor
  threads. Cancellation and current-thread heartbeat tests exercise accepted-operation ownership.

## Queue behavior and query surface

- Multi-claim continuations commit atomically, preserving lease validation and side-record/fence updates as
  one authoritative transition.
- Explicit eligibility-time claims and filtered lifecycle metrics are available through the shared engine
  contracts, with recovery and cross-backend coverage.
- Deferred group-commit tests and performance workloads now actively poll concurrent operation windows,
  preserving batching without relying on eager future construction.

## Turso qualification progress

- The feature-gated Turso adapter shares the relational command model and now has SQLite differential tests
  for lifecycle state, versions, cursors, definitions, reclaim selection, cohorts, filtered reads, gates,
  typed indexes, summaries, and rollback behavior.
- New recovery tests cover reopen, genesis replay, overlap idempotency, gap rejection, and local projection
  loss. Concurrency tests cover 16 disjoint writers and a same-active-key conflict; cancellation tests require
  zero-or-one replayable outcomes with no stranded subsequent writer.
- The object-log plus Turso server profile remains disabled. Full ProjectionImage/read differential coverage,
  server wiring, and the focused CI lane remain tracked work and are not release claims in v0.19.0.

## Release boundary

- E2 cross-queue scale/density and E3 object-log load evidence both run in the release workflow. Portable
  gates use same-run ratios, bounded degradation, progress, batching, and exact recovery; absolute capacity
  remains reported evidence tied to an explicitly declared deployment topology.
- The release gate also requires host-independent correctness evidence, PostgreSQL transaction-pair proof,
  coverage, build closure, Helm validation, packaging, and the kind storage matrix. Governed release-tier
  E0-E3 evidence remains a separate repository policy gap explicitly reported by the gate.
- The workspace MSRV remains Rust 1.92. Object-log v2 remains the default writer; readers retain support for
  interleaved v2/v3 history.

## Verification

- Full object-log, PostgreSQL, and server suites passed after the async-boundary migration, including the
  group-commit and hybrid performance gates.
- Turso's complete feature-gated test suite and the pqueue-conformance integration suites passed.
- Warning-denied Clippy, formatting, workspace checking, and diff hygiene passed for the affected crates.

# pqueue v0.17.3

## Fixes

- Embedded object-log plus SQLite verification drains already-admitted asynchronous checkpoints before
  comparing SQLite with the authoritative log, closing the sequence-1 versus sequence-0 lifecycle race.
- The barrier remains verification-specific, so projection deletion and rehydration can recover by
  discarding deferred work and replaying authoritative history.

## Release workflow

- The source release gate runs exactly once inside the deployment gate; workspace tests and coverage are
  not repeated before the kind storage matrix.
- Quiet-host E2 evidence is explicitly deferred for v0.17.3. Shared runners skip the scaled cross-queue and
  1,000-queue density workloads, retain the host-independent E2 judgment contract, and record
  `e2_smoke_status: deferred_quiet_host` in deployment proof.
- The lightweight E3 smoke rows emitted by workspace correctness tests remain required and strict-valid.
  This does not substitute for the deferred governed E3 cost and 10-million-item recovery measurements.
- The deferral is version-bound; the next release must make a new explicit decision.

## Release boundary

- Niflheim remained in service. The governed quiet-host density and release-tier E3 cost/recovery
  measurements remain deferred, and this release makes no new performance claim from them.
- Production governed-tag wiring remains open. `objectlog/hybrid-strict` remains experimental through
  direct environment or configuration only.
- The workspace MSRV remains Rust 1.92 and no data migration is required.

## Verification

- Warning-denied Clippy, workspace correctness, exact Postgres TP003 evidence, E3 smoke presence, coverage
  bars, build closure, Helm checks, and the four-combination kind storage matrix remain enforced.
- The async checkpoint regression and repeated lifecycle interleaving tests pass.

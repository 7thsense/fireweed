# Fireweed Queue v0.20.0 public preview

v0.20.0 is the first public preview release under the Fireweed Queue identity.
It completes the hard pre-release namespace cutover defined by
[ADR-023](../helix/02-design/adr/ADR-023-pre-release-fireweed-namespace-cutover.md).
Current packages, APIs, commands, configuration, wire identifiers, schemas,
storage roots, artifacts, and repository coordinates use Fireweed names only.
There are no deprecated aliases, fallback reads, compatibility binaries,
dual-writes, or migration shims.

Existing development databases and object-store namespaces must be recreated.
Immutable execution history and historical release evidence remain unchanged
where rewriting them would falsify the audit record; they are not accepted as
current product identifiers.

## Changed

- The public display name is Fireweed Queue, with Fireweed as the short name.
- The first renamed release is versioned v0.20.0.
- Rust embedders now construct one concrete, backend-erased `Fireweed` handle.
  Storage authority, projection, coordination, schema, and node choices are
  supplied only through `open_*` functions and role-named construction config;
  they cannot be inspected or downcast after construction.
- Queue operations—including append, claim, commit, mutation, query, metrics,
  and finalization—are inherent methods on `Fireweed`. Disposable projection
  maintenance is available separately through borrowed
  `projection_control()` capability.
- The generic `Fireweed<B>`, raw `LibBackend` injection, `EmbeddedFireweed`, and
  the retired `Embedded*` Rust configuration surface are no longer available to
  downstream crates.
- The source Helm chart remains independently versioned for development. The
  v0.20.0 release package overrides its chart and application versions to
  `0.20.0`; its chart, package, and evidence names are Fireweed-native.
- Persisted data names and wire identifiers use the Fireweed namespace. This
  release does not read or migrate development data written under a retired
  namespace.
- Historical release and audit identifiers remain unchanged for traceability.

## Cutover

The rename is intentionally breaking because no stable public Fireweed release
preceded v0.20.0. Consumers must use the `fireweed` package and repository,
`Fireweed` API, `FIREWEED_*` configuration, and fresh Fireweed storage roots.
Only immutable audit identifiers, literal historical evidence, and negative
tests may mention the retired identity; none is an executable compatibility
surface.

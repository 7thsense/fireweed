# pqueue v0.19.4

v0.19.4 is a correctness and reliability release for embedded object-log,
SQLite, PostgreSQL, and async-runtime deployments.

## Filtered object-log claims

- Filtered claims now traverse authoritative object-log projections. The
  object-log/SQLite composition reports the capabilities its projection really
  implements and forwards range scans instead of falling through to
  `Unavailable`.
- Filtered claims remain available after projection deletion, rebuild, and
  process reopen. Caller-supplied eligibility and lease times remain
  authoritative.
- This fixes the pqueue v0.19.3 failure that prevented Snorri's interrupted
  object-log rebuild scenario from reaching its first durability barrier.

## Runtime and shutdown reliability

- The process-wide blocking pool reserves a bounded coordination lane for
  ownership establishment and fencing. Coordination may wait on queue-affine
  data work, but data work never enters or waits on the coordination lane, so
  saturated queues cannot form a cyclic pool deadlock.
- Embedded blocking work remains shared across handles and queue-partitioned;
  dropping a final handle does not synchronously join worker threads.
- Hybrid projection maintenance no longer keeps the backend or resident byte
  permits alive merely because a maintenance job is waiting for blocking-pool
  admission. Maintenance begins on its configured cadence rather than an eager
  first tick.
- Server shutdown drains or aborts owned reclaim, ownership, Fjord, and
  projection-maintenance tasks instead of leaving accepted work detached.

## Storage correctness

- PostgreSQL and SQLite reclaim paging is partition-aware and bounded.
- Claim-by-query replay and renewal retain request identity, worker attribution,
  and lease expiry across recovery.
- PostgreSQL ownership, migration, projection writes, and object-log append
  paths use bounded set operations and fixed shared resources.
- SQLite grouped push, group summaries, compose-log operations, recovery
  catalogs, and projection maintenance preserve batch semantics downstream.

## Verification

- The unchanged Snorri interrupted-rebuild CLI proof fails on v0.19.3 and
  passes against this release.
- Filtered object-log/SQLite claim, projection delete/rehydrate, interrupted
  rebuild, ownership saturation, cancellation, and shutdown regressions pass.
- Workspace formatting, tests, warning-denied Clippy, HELIX validation, release
  packaging, checksums, and artifact verification are executed from the tagged
  revision before publication.

The performance observations emitted by scale harnesses are topology-specific
capacity data. This release does not use quiet-host deferrals or fixed
host-speed thresholds. Additional batching and in-memory indexing work is being
delivered separately rather than delaying this reliability release.

# pqueue v0.19.4

## Correctness and scale

- Filtered claims now traverse authoritative object-log projections correctly,
  including after deleting and rebuilding an embedded SQLite projection.
- The full-async Turso projection matches SQLite command, read, cancellation,
  reopen, and local-file-loss behavior, with a feature-gated server profile and
  one focused CI lane.
- Segmented object-log head publication now performs constant metadata work per
  seal. Immutable successor CAS still fences stale owners without rescanning the
  complete historical head set.

## Release evidence

- E0 through E3 release gates use exact outcomes, logical progress, bounded
  resources, same-run controls, and exact recovery. Quiet-host requirements and
  absolute host-speed pass bars are rejected.
- The tag gate consumes named exact-revision authorities and an attested,
  deterministic evidence archive with a verified SHA-256 sidecar.
- `objectlog/hybrid-strict` remains experimental through environment or direct
  configuration only. The Helm schema and its named negative gate continue to
  exclude it from public deployment support.

## Verification

- The release candidate must pass the workspace tests and warning-denied Clippy,
  HELIX graph audit/validation/staleness checks, Helm/deployment gates, exact
  1,001-queue density evidence, and the governed E3 10-million-item recovery and
  fencing contract before publication.

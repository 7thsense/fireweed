# Fireweed v0.32.0 — Queue only

This source-preview release is breaking. The `fireweed` crate now exposes the
API-007 `Queue` and nothing else; the server, RESP, container and Helm
deliverables are gone; and persisted data written by earlier builds is refused
instead of migrated. Fireweed is pre-1.0 and keeps no compatibility layer.

## Breaking changes

- **`Queue` is the only public API.** The pre-`Queue` `Fireweed` facade, its
  builders and its tests are removed, along with the `fireweed-workload` crate
  and the facade-bound benchmark, example and PostgreSQL tests. Entry points are
  `Queue::postgres`, `Queue::s3_turso` and `Queue::ephemeral_disk`
  ([API-007](../helix/02-design/contracts/API-007-queue-claim-commit-contract.md)).
- **No server, RESP, images or charts.** The `fireweed-server`, `fireweed-resp`
  and `fireweed-loadgen` crates, the Dockerfiles, the Helm chart, kind tooling
  and the image and binary packaging are deleted. A release publishes the source
  archive, SBOM, checksums and provenance only.
- **Old persisted data is refused.** The legacy readers and migrations are
  removed: the FWQL1 queue-log reader and writers, the `catalog.json` reader,
  the legacy JSON batch, integer-array bytes and tagged-metadata decoders, the
  Turso upgrade migrations, the relational claim outbox, the Postgres operator
  migration machinery and the deprecated Postgres, server and conformance
  aliases. `canonical_sha256` is the only push fingerprint, and unframed queue
  definitions are refused. Recreate the data; nothing is converted.
- **PostgreSQL stores a schema version and refuses a mismatch at open.** Each DDL
  family records its version in `fireweed_schema_version`, checked under an
  advisory lock. The `queue_store` component is at version 3 (version 2 added the
  retention columns, version 3 the field-presence index). A database from an
  earlier build, or tables that predate the check, are refused and must be
  recreated.
- **`QueueSchema.retention` has no default.** Provisioning declares
  `request_id_nanos` (the replay window for request ids, greater than 0) and
  `deleted_keys`, either `Reusable` or `Retired { window_nanos }` (at least
  `request_id_nanos` plus 5 minutes).
- **`issued_at` is required** on every insert, claim and commit group, and on
  each id passed to `read_commit`. The caller takes it once per request id and
  resends it unchanged on retries. The same id with a different `issued_at` is
  `RequestConflict`; an `issued_at` more than 5 minutes ahead of the queue clock
  is `Invalid`; an id older than the retention horizon is `Expired` with no
  lookup. Cleanup runs in the background and advances the horizon, and a
  renewed claim holds the horizon for its lease.

## Additions

- `Queue::s3_turso` and `Queue::ephemeral_disk` constructors, with one
  projection database per owned queue, a refusal of a second handle on a cache
  directory, and a lease that no longer expires mid-request.
- `Predicate::Present` and `Predicate::Absent` for field-presence filters, backed
  by an index in the Turso projection and the PostgreSQL queue store.
- `Queue::limits()` and `Queue::ephemeral_disk_with(limits, runtime, clock)`.
- Nightly functional fixtures, with PostgreSQL and RustFS provided to the job.
- Large-scale tests moved to their own tier to cut per-push CI usage.

## Migration for facade users

Move to `Queue`. The facade, `fireweed-server` and RESP have no replacement in
this repository. TD-011 in the Snorri repository describes the migration.
Provision each queue with an explicit `retention`, persist `issued_at` with each
request id, and recreate any Postgres, object-log or Turso data from earlier
builds.

## Qualification

Measured source: recorded in `v0.32.0.source-preview.json`. The tag points to a
later evidence commit; archives are built from that measured source. The
validation record and its logs are committed with the evidence commit as
`v0.32.0.validation.json`.

This source preview does not claim governed product-ready P20pr deployment
qualification, signing, or new capacity measurements. The public storage cell
remains S3 object-log × Turso × async projection.

## Identity policy

The pre-S reserved identity is `v0.32.0`; synchronized workspace packages use
`0.32.0`. The independent benchmark tool and gate-set versions retain their
independent coordinates. Before tagging:

```sh
bash scripts/release/list-public-version-sources.sh v0.32.0
bash scripts/release/verify-release-identity.sh --version 0.32.0
```

An explicit source-preview manifest selects the prerelease packaging route.

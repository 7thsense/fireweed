# Fireweed v0.31.29 — live Turso projection lifecycle

This source-preview prerelease implements live projection maintenance for
object-log × Turso cells. It is not a governed product-ready P20pr deployment
qualification and does not establish workflow capacity readiness for a Snorri
production migration.

## Changes

- Filesystem and S3 object logs with a Turso projection expose
  `Fireweed::projection_control()` with verify, delete, and rebuild, matching
  the Postgres projection maintenance handle.
- Delete wipes owned projection tables on the connected writer and refreshes
  the serving reader. The authoritative log is untouched.
- Full rebuild on an empty live connection replays one command at a time so
  mixed Push, UpdateFields, and MutateItems do not conflict. Incremental
  catch-up still uses 256-command pages.
- Facade tests that exercise verify, delete, or rebuild call
  `projection_control`. Unlinking projection files and reopening is not a
  substitute. CI forbids that stand-in in public facade tests. Crash-loss
  rebuild-on-open remains in server and workload recovery suites.
- Memory projections stay without a maintenance handle. Postgres-log × Turso
  is unchanged.
- Opt-in produce traces can join to physical store identity and start
  timestamps. Traced results still cannot qualify capacity.

The log remains the sole durability authority. Projections remain
reconstructible from that log.

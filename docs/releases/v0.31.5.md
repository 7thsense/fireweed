## Headline

**Native FWC1 durable command codec** on the product log path, with
**client-controllable typed indexes as native `TypedValue`s** (not JSON entity /
Base64 payload on the log). In-tree multi-worker snorri-shaped probe on
`open_sqlite` (sqlite log × memory projection) measures **~13–16k durable tps**.

## Cut contents

### Native log codec

- **FWC1 frame** (`postcard`): durable envelopes are binary only — legacy JSON
  rows are rejected on read (no dual-read).
- **Core primitives** pack natively (`ItemId` as `u64`, timestamps/bools/ints).
- **Payload / fields** remain exact byte **blobs** on the durable path (no Base64).
- **Client indexes:** `index_fields: BTreeMap<field, TypedValue>` is the durable
  middle ground (`String` / `Integer` / `Float` / `Bool` / `DateTime`), declared
  by `create_queue.typed_indexes` and supplied on push. Admission may still accept
  a JSON entity for ergonomics and materialize native fields once.

### Performance

- `claim_finalize_push_cycle` (from v0.31.4) + native encode → higher durable tps
  on the same product cell.
- Encode size: snorri-shaped push ~36% smaller than JSON; claim×500 ~63% smaller.

### Evidence

- `docs/perf/evidence/tp005/multi-worker-tps-latest.md`
- Probe: `cargo test -p fireweed --test sqlite_multi_worker_tps_probe --release --features sqlite -- --nocapture`
- Confirmed (release cut run): w1 **~13.1k**, w4 **~13.7k**, w8 **~16.5k** durable tps.

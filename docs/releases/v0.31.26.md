# Fireweed Queue v0.31.26 — sustained mutable workflow capacity

This release is a source-preview product pin. It contains the public API workload
harness and the fixes qualified at million-record scale. It is not a governed
product-ready P20pr deployment evidence promotion or an S3 performance claim.

## Changes

- Update each original workflow row through enrichment, scheduling, delivery,
  retries, outcomes, and retention using lease/version-guarded mutations.
- Preserve payloads without rewriting them when a mutation changes only metadata.
- Batch projection work, fuse compatible claim/mutation application, and avoid
  broad queue scans and redundant auxiliary writes.
- Fix caller-owned response delivery and retain projection coverage barriers,
  fencing, replay, and authoritative-log durability.
- Backport effective automatic WAL checkpoint configuration and repair stale
  Turso page-cache accounting that caused repeated full-cache scans. The five
  vendored Turso 0.7.2 packages include licenses and explicit patch provenance.
- Add deterministic public API workflow, primitive, recovery, fairness, and
  bounded-storage tests, plus a repeatable qualification command.

## Measured capacity

Two runs of each workload at production source `b0f89563`, with the same binary:

| Operation | Records/sec |
|---|---:|
| Insert | 72,832–94,091 |
| Enrich by key | 69,567–74,363 |
| Schedule by ID | 38,956–40,350 |
| Complete full three-stage workflows | 7,873–8,029 |

The primitive runs each used one million rows. Each workflow run recycled
500,000 recipients through six cycles (three million lifecycles), with retries,
failure outcomes, exact payload checks, and purging. Every required throughput,
correctness, and sampled storage check passed. Configuration: 16 physical shards,
eight workers per shard, 1,000-row batches, approximately 1 KiB deterministic
compressible payloads, filesystem log and disk-backed Turso projections on one
Ryzen 7 4800H host. These are individually addressed updates in batches, not
10,000 separately fsynced RPCs/sec. Enrichment handlers are deterministic stubs.

Validation: 106 public workload/adapter release tests passed (one existing
ignored); 46 native cache/pager tests passed (one existing ignored). The release
version bump does not change the measured production implementation.

See the [capacity review](../helix/04-build/workflow-capacity-review.md) for raw
reports, failed experiments, workload mapping, and qualification limits. Repeat:


## Compatibility

New readers support existing logs. The new payload-preserving replacement log
variant requires an updated reader: after writing it, rolling back to an older
binary that lacks this variant is unsupported. Existing projection page sizes
are retained; newly created projections use 4 KiB pages. The log remains the
sole durability authority. Snorri integration migration is separate work.

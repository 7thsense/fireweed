# Fireweed v0.31.31 — one public cell

This source-preview prerelease records the public product as one cell: an
object-log published to S3, a Turso projection, and async log acknowledgement.
It is not a governed product-ready P20pr deployment qualification, and it does
not claim the 10k or 12.5k campaign floors.

## Product

- Callers, the server, and Helm open S3 × Turso with `AsyncProjection` only.
  A successful mutate means the object log has the bytes. The next claim polls
  Turso and may be empty.
- There is no public storage matrix and no Strict barrier. Selectors other
  than this cell fail closed before storage I/O. That rejection is not a
  roadmap.
- S3 is the public publication adapter of `fireweed-objectlog`. Filesystem
  publication stays inside that crate for the same log protocol on one local
  process. It is not a Fireweed support cell.
- Non-durable tests and small benches use Turso `:memory:`, the same SQL
  projection with no WAL file. WAL, reopen, and rebuild tests use a temporary
  Turso file. The separate in-memory map is not coverage of this cell.
- ADR-024 is the storage law. The 2026-09-17 twelve-cell amendment is
  historical.

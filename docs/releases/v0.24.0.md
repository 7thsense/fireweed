# Fireweed Queue v0.24.0 public preview

v0.24.0 collapses the dual-stack composition model onto async-only product
paths and cuts the object-log axis over to crates.io `object-log` 0.2
(`LogEngine`), deleting the in-tree segmented FWSG substrate.

## Highlights

- **Async-only product composition** — memory, sqlite, and postgres
  log-replay families assemble through `AsyncLogReplayBackend` (and thin
  factories). Family product type aliases are removed so call sites stay on
  the generic product / port traits.
- **Object-log on crates.io LogEngine** — production object-log × memory,
  sqlite, hybrid, and postgres cells open via `ObjectLogEngineStore` and
  `AsyncObjectLog*Backend` products. Segmented FWSG, hand-rolled S3 client,
  and actor-over-sync `AsyncObjectLog` are removed.
- **Sync `ComposedBackend` deleted** — no public dual-stack product
  composition remains. `LogStore` / `ProjectionStore` stay as axis traits
  under in-process bridges used by async composition.
- **Server open matrix** — durable and object-log start arms wire async
  products; object-log no longer depends on segmented flusher pools for the
  LogEngine path.
- **Tracker** — epic `fireweed-31ff84a0` (`plan-async-objectlog-2026-07-31`)
  and its child beads are closed.

## Breaking / migration notes

- On-disk object-log segment format from the retired FWSG substrate is **not**
  compatible with LogEngine objects. Plan a new storage generation for
  object-log deployments.
- **Open semantics (FWSG residue):** product opens fail closed with a stable
  `EngineError::Storage` message containing
  `INCOMPATIBLE_OBJECT_LOG_GENERATION` (or `MIXED_OBJECT_LOG_GENERATION` when
  LogEngine keys coexist with FWSG markers). Match via
  `fireweed_objectlog::is_incompatible_generation_error`. This is intentional
  fail-closed behavior, not undefined reads.
- **Migration procedure and detection guidance:** see
  [docs/operator/object-log-storage-generation.md](../operator/object-log-storage-generation.md)
  (regenerate under a fresh root/prefix; no in-place FWSG→LogEngine converter).
- Product APIs that named family backends (`ComposedMemoryBackend`, etc.)
  should use factories and `AsyncLogReplayBackend<…>` or port traits.
- Turso projection on object-log remains feature-gated; the prior segmented
  Turso open path was removed with the substrate.

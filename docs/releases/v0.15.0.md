# pqueue v0.15.0

## Highlights

- Claim eligibility can now be evaluated at a caller-supplied epoch, giving orchestrators a stable boundary for due-work selection and lease handoff.
- Object-log recovery and reclamation now preserve permanent-head, retention-floor, deletion-watermark, and branch source-pin guarantees across legacy-manifest deletion and restart.
- SQLite/object-log composition now surfaces deleted-manifest-prefix inconsistencies explicitly and fails closed when a recovered projection image is behind the durable floor.

## Reliability and safety

- Reconciles reset lease epochs with durable storage fences after restart, preventing stale owners from regaining authority when in-memory ownership state is rebuilt.
- Keeps legacy manifest bootstrap conservative, prefers the permanent head when present, and reconstructs or persists manifest deletion progress without reopening reclaimed prefixes.
- Retains below-floor source objects while a readable branch still pins them and fails closed when a branch source-pin record is missing or unreadable.
- Preserves trimmed-source branch reads on the branch live view and validates final-readable-branch deletion behavior.

## Release engineering

- Release and CI scripts invoke the pinned Rust 1.92.0 toolchain explicitly, including nightly coverage subprocesses where branch instrumentation requires it.
- The tag workflow now invokes the documented smoke-only release gate without unsupported release-tier arguments, and the gate rejects unexpected arguments instead of silently ignoring them.
- The smoke gate proves workspace tests, formatting, clippy, E2/E3 smoke-ledger evidence, coverage floors, and build-closure integrity. The v0.15.0 tag workflow does not ingest or assert the repository-held release-tier E0-E3 evidence.

## Upgrade notes

- This is a backward-compatible feature release. No storage migration is required.
- Existing object-log deployments gain stricter fail-closed recovery behavior. Operators should investigate deleted-manifest-prefix or missing source-pin errors rather than bypassing them.
- GitHub release assets include one x86_64 Linux binary archive, a Helm chart, checksums, and container-image evidence. No macOS binary was published. The workflow publishes the service image to GHCR; it does not publish crates to crates.io.

## Verification

- Focused Fjord configuration, wire/producer, startup-readiness, terminal-reap, and hot-projection suites were revalidated while reconciling the historical cancelled work items.
- The final release commit is gated by the repository bootstrap and enforcing CI lanes, the deployment release gate, package dry runs, and the pushed-main GitHub Actions matrix before the `v0.15.0` tag is published.

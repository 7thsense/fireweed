# Fireweed Queue v0.23.0 public preview

v0.23.0 adds the storage-axis adapters and the provider-neutral S3 recovery
release path needed to measure an object-log deployment through its real
authority store.

## Storage composition

- `StorageConfig` now represents the supported log, projection, authority, and
  durability axes for server and Helm deployment configuration.
- S3 object-log composition requires native conditional-write authority. An
  endpoint that cannot prove that primitive is unsupported; Fireweed does not
  add a second storage authority as a fallback.
- The public preview documentation now classifies the supported matrix and
  makes hybrid or unverified combinations explicit rather than implying
  support.

## Provider-neutral E3 runner

- `scripts/perf/tp002-e3-s3.sh` is the governed S3 entrypoint. It requires an
  explicit provider adapter, bucket lifecycle declaration, isolated run
  namespace, and operator-declared topology; the MinIO wrapper remains a
  local-convenience adapter only.
- Each run gets a fresh evidence directory and non-secret composition
  fingerprint. Cleanup is restricted to that run prefix and occurs only after
  successful sealing and semantic verification; failures preserve the
  namespace for inspection.
- E3 contracts are now schema v4 and fencing evidence schema v5. A shared run
  identifier and composition fingerprint bind the manifest, ledger,
  transactions, and native S3 fence result.

## Release evidence boundary

This source release does not claim a new live 10-million-item E3 pass. A
Garage proof must use rotated, dedicated credentials and an isolated bucket
and prefix. It must first pass the native conditional-create capability probe,
then be published as exact-revision governed evidence before a production
publication workflow can attest that proof.

## Upgrade notes

- Consumers of E3 evidence must emit the v4/v5 linked artifacts; mixed or
  older schemas are rejected fail-closed.
- Existing queue API behavior, including the v0.22.0 request-id push
  disposition, is unchanged.
- crates.io and GHCR publication remain deferred. This is a GitHub source
  release under `MIT OR Apache-2.0`.

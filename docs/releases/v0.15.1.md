# pqueue v0.15.1

## Highlights

- Release publication now includes JSON and Markdown deployment proof bound to the final release commit, Helm package version, container-image tag and digest, and checksummed distribution.
- Release artifact verification fails closed when deployment proof is missing, failed, malformed, or inconsistent with the chart, image evidence, or expected commit.
- The production-readiness contract and v0.15.0 notes now distinguish shipped Linux artifacts, optional TLS builds, exact-profile transaction evidence, and smoke-only versus repository-held release-tier evidence.

## Release engineering

- The tag workflow finalizes deployment proof only after the versioned chart and container-image evidence exist, then regenerates `SHA256SUMS` before publishing.
- Positive and negative release-artifact fixtures run in the enforcing PR gate.
- The smoke release gate no longer describes existing release-tier E0-E3 evidence as unperformed; enforcing integration of that governed evidence remains tracked by `pqueue-bf46289d`.
- DDx release planning now tracks exact Postgres storage-pair evidence and live-kind coverage for object-log projection combinations under epic `pqueue-c4e5f691`.

## Dependency maintenance

- Updated the Redis lockfile dependency to 1.4.0.
- Updated `rustc-hash` to 2.1.3 and `bytes` to 1.12.1.
- Updated the release and CI Helm toolchain within the supported 3.x line to 3.21.3.

## Upgrade notes

- This is a backward-compatible patch release with no storage migration or public API change.
- The stock binary continues to support plaintext Postgres. Native TLS remains available only to source or custom builds enabling the `tls` Cargo feature.
- Published binary archives remain x86_64 Linux only; no macOS binary is claimed.
- Release assets now include `deployment-proof.json` and `deployment-proof.md` in addition to the binary archive, Helm chart, image and chart evidence, and checksums.

## Verification

- The release commit is gated by formatting, clippy, workspace tests, smoke-tier E2/E3 ledger validation, coverage thresholds, build-closure checks, Helm validation, and the live-kind deployment matrix.
- The tag workflow semantically verifies that deployment proof matches the final release version, commit, chart package, and container-image evidence before publication.

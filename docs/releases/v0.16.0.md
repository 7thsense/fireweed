# pqueue v0.16.0

## Highlights

- Production configuration can now select a shared S3-compatible segmented object log and a shared Postgres ownership control plane without test-only environment variables.
- Multi-replica ownership now advertises pod-reachable endpoints, returns one-hop `MOVED` redirects, and keeps endpoint refresh bounded per node rather than per queue.
- Shared object-log ownership uses one versioned authority head for both epoch fences and visible log-tail commits, preventing stale writers from publishing after handoff.
- New generated bootstrap inventories support deterministic deployments of up to 10,000 queues without hand-writing queue lists.

## Durability and routing

- Newly allocated Postgres leases remain `PendingFence` and cannot serve, renew, or drain until the exact object-log epoch is durable and transactionally confirmed.
- Fence failure, failed compensation, and process restart remain fail closed; after lease expiry, a higher epoch can recover the queue without reusing the failed epoch.
- Immutable object-log candidates become visible only through the authoritative head CAS. Recovery rejects version holes and authority-prefix loss, ignores losing candidates, and bounds traversal at the durable read horizon.
- Live Postgres and MinIO tests cover fence-before-serve ordering, concurrent acquisition, stale append handoff, one usable owner, failed compensation across restart, and higher-epoch recovery.

## Deployment and release engineering

- Live-kind coverage now includes object-log/SQLite, object-log/hybrid, and object-log/hybrid-async restart/readback profiles in addition to the existing matrix.
- Exact Postgres/SQLite and Postgres/Postgres TP-003 transaction evidence is regenerated from live Postgres in CI and verified fail closed before release.
- Release evidence freshness is bound to the exact source commit and tag; stale or mismatched attestations no longer satisfy the gate.
- The tag workflow now requires the tag version to equal the Cargo workspace version, requires the tagged commit to equal `origin/main`, and publishes these versioned release notes.

## Upgrade notes

- This is a backward-compatible feature release. Existing local single-replica object-log deployments continue to use their existing manifest path.
- Shared multi-replica S3 ownership requires both the S3 object-log configuration and the Postgres control plane. A non-empty legacy queue without the unified authority marker fails closed rather than attempting an unsafe online adoption; migrate it offline or start a new shared namespace.
- Multi-replica service configuration requires an explicit pod-reachable `PQUEUE_ADVERTISE_ADDR`; unspecified, port-zero, and malformed endpoints are rejected.
- `objectlog/hybrid-strict` remains experimental through direct environment/configuration only and is not chart-selectable.

## Claim boundary

- This release proves the ownership and durability races above plus the shipped live-kind profile matrix and exact Postgres transaction pairs.
- It does not claim completed release-tier 1,000-queue density, both-profile E2 scaling, or the full four-bound E3 latency/cost/recovery matrix. Those governed performance beads remain open and require uncontaminated measurements on a quiet host.
- The replica-safe S3 object-log/SQLite Helm profile and live failover benchmark remain follow-on work; the lower-level shared storage, control-plane, routing, and fencing primitives ship in this release.

## Verification

- The release commit is gated by formatting, warning-denied Clippy, workspace tests, exact live Postgres transaction evidence, live Postgres+MinIO ownership tests, smoke-ledger validation, coverage thresholds, build closure, Helm validation, release packaging, and the live-kind deployment matrix.
- Release assets include the x86_64 Linux service archive, Helm chart, container-image evidence, deployment proof in JSON and Markdown, and `SHA256SUMS`.

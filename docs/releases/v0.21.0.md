# Fireweed Queue v0.21.0 public preview

v0.21.0 completes the external Rust embedding surface needed by Snorri while
keeping storage composition behind one concrete `Fireweed` handle. It is a
GitHub source release. Publication to crates.io and GHCR is deferred.

## Embedded facade

- Every supported constructor returns the same backend-erased `Fireweed` type.
  Log, projection, schema, node, coordination, and response-barrier choices are
  construction inputs only; callers cannot inspect or downcast them afterward.
- Queue creation, append, claim, commit, mutation, query, metrics, and
  finalization are inherent `Fireweed` operations. Disposable projection
  maintenance remains the sole optional concern through
  `projection_control()`.
- The facade exports `ItemMutationSnapshot`, `ItemMutationSummary`, selectors,
  predicates, preconditions, patches, operations, and per-item outcomes needed
  to inspect and apply atomic item mutations without importing internal crates.

## Mutation and replay correctness

- Addressed and selector-based mutation now preserve complete item state across
  memory, SQLite, PostgreSQL, and composed object-log profiles. Dry runs leave
  no durable effect; failed preconditions roll back atomically; lease-changing
  mutations invalidate stale claim authority.
- Retained request identity covers enqueue and claimed-work commit paths.
  Replaying the same request body returns the original result, while reusing a
  request ID with a different body returns `RequestIdConflict`.
- Object-log replay resolves retained commit requests from durable authority,
  including after projection loss, restart, and prefix trimming.

## Validation and durability

- Queue gate, group, and cohort policies are validated consistently at the
  facade boundary. Invalid item shapes or gate operations fail before append;
  policy-specific fixtures no longer combine incompatible queue modes.
- Object-log deletion and bounded reclamation share one accounting path, so
  public segment counters agree with physical deletion and maintenance
  reports.
- The current object-log format is strict. Unsupported pre-release formats and
  alternate monolithic storage paths are not compatibility surfaces.
- The complete functional and durability matrix covers memory, SQLite,
  PostgreSQL, object log with SQLite projection, and object log with PostgreSQL
  projection. Environment-backed rows must execute without skips before the
  release checklist can record a go decision.

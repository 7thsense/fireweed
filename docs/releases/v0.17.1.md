# pqueue v0.17.1

## Fix

- Embedded object-log plus SQLite verification now checkpoints every already-admitted asynchronous
  projection batch before comparing SQLite with the authoritative log. This closes a lifecycle race in
  which an immediate verification could observe log sequence 1 while SQLite was still at sequence 0.
- The checkpoint barrier is verification-specific. Projection deletion and rehydration continue to
  discard deferred work and rebuild from authoritative history, including recovery from a poisoned
  checkpoint.
- A public-facade regression holds the background checkpoint worker outside the test window and proves
  that verification itself drains the deferred checkpoint. The original lifecycle interleaving test also
  passes repeated execution.

## Release boundary

- This patch carries the v0.17.0 feature set and its compatibility guarantees. The workspace MSRV remains
  Rust 1.92 and no data migration is required.
- Niflheim remained in service. The quiet-host 1,001-queue density diagnostic and release-tier E3 cost plus
  10-million-item recovery measurements remain deliberately deferred; this release makes no new claim from
  those rows.
- Production governed-tag wiring remains open, and `objectlog/hybrid-strict` remains experimental through
  direct environment or configuration only.

## Verification

- Warning-denied Clippy passes for the affected crates and all targets/features.
- The deterministic deferred-checkpoint regression passes, and the formerly flaky lifecycle interleaving
  test passes 20 consecutive repetitions locally.
- The GitHub release workflow reruns the exact Postgres TP003 proof, full release gate, deployment gate,
  packaging, and publication from the tagged revision.

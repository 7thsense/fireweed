## Headline

v0.31.5/6 native FWC1 features become **consumable** for Snorri-shaped
claim/echo: byte maps round-trip as raw bytes on the native path, and the
in-memory projection can rehydrate a dropped entity from `index_fields`.
Same cut pins the workspace to **Rust 1.97.1** and coalesces concurrent
`claim_finalize_push_cycle` seals so sqlite×sqlite **w8 no longer collapses
below w1**.

## Cut contents

### FWC1 / Snorri consumability (`250a83cb`, `4443c7ca`)

- Native serialize of `btreemap_bytes` / `btreemap_option_bytes` / `vec_vec_u8`
  writes raw bytes (JSON still Base64). Postcard str/bytes framing no longer
  stores Base64 text that decodes as the field value.
- In-memory `ProjectionData` rehydrates a missing entity document from native
  `index_fields` at apply (claim echo / filters / merge on `projection=memory`).
- Leftover `PushSpec.index_fields` initializers in tests/server.

### Toolchain

- `rust-toolchain.toml` and workspace MSRV: **1.97.1** / **1.97** (was 1.92.0).
- Language edition remains **2024** (latest stable edition).

### Concurrency

- Cycle group-commit sealer: concurrent `claim_finalize_push_cycle` callers on
  one shard share one select + one append+apply. w1 is still one waiter / one
  seal.

### Evidence

- `docs/perf/evidence/tp005/sqlite-projection-tps-latest.md`
- Warm sqlite×sqlite sealer probe: w1 **9,061** / w4 **10,333** / w8 **10,697**
  (5 seals / 16 cycles). Host-bound vs the v0.31.6 12k machine; ratio is the
  concurrency goal (w8/w1 = 1.18).
- Snorri adapter gate on the consumability branch: 150/150 both checkpoint
  modes (reported by the Snorri cut; not re-run on this host).

## Known remaining (not this cut)

Entity rehydrate is **memory-projection only**. SQLite/Turso/Postgres still
echo `entity: None` after admission drop; Postgres/Turso still key typed
indexes from `entity_document` and do not persist `index_fields`. That is
reserved follow-on work, not a v0.31.7 claim.

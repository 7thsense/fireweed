### Verdict: BLOCK

### Summary

This is partly “just use SQL”: reader connections for reads and one SQL lease transaction for claim are the right direction. But the duplicate-push skip, no-tail claim ordering, and under-specified per-key waits are workarounds with correctness holes, not merely efficient use of the projection. Dropping full-shard catch-up may be viable only if the plan defines precise ordering barriers, idempotency behavior, outbox recovery, and adapter contracts without inventing a second item authority.

# API-009: Space schemas as UMF documents

**Type**: Document mapping and UMF extension (`fireweed.space` 0.1.0)
**Version**: v1
**Status**: proposed. Resolves ADR-027 question 39 (D34, D43, D44).
**Related**: ADR-027, API-008, UMF CONTRACT-081 (`umf.tables`), UMF CONTRACT-084 (JSON values and sets)

A space schema (API-008 §Schema documents) can be written as a UMF core
0.10.0 document. Fireweed has no separate schema language for it:
- core Records, Fields and Keys give the logical model;
- `umf.tables` (profile `postgresql18/0.1`) gives the physical tables,
  columns and indexes, and UMF compiles their PostgreSQL 18 DDL;
- the `fireweed.space` extension, owned by Fireweed and registered at
  runtime through `umf-codegen`'s registry, carries the queue, table and
  read semantics UMF core doesn't have.

The crate `fireweed-umf` implements this contract:

| Function | Does |
|----------|------|
| `resources()` | UMF's release resources with `fireweed.space` registered (`CodegenResources::register_host_extension`) |
| `export(schema, names)` | The canonical UMF document for an API-008 `Schema` |
| `load(resources, text)` | Reads a UMF document (YAML or JSON) and returns the `Schema` it declares |
| `derive(document)` | The `Schema` a document declares, without the checks `load` makes |
| `deployment(resources, loaded, config)` | UMF's PostgreSQL 18 deployment bundle for the document's tables |
| `Semantics` | The `fireweed.space` semantics as UMF host capabilities |

The extension package is `schemas/umf/fireweed-space-0.1.0.package.json`.

## The document

A space is one module. Its `fireweed.space` payload is:

```yaml
kind: space
version: 2                      # the schema's version
requestRetention: 86400000      # milliseconds
queues:
  instances: {record: {module: space, element: instances}, maxAttempts: unlimited, retention: 2678400000, priority: asc}
tables:
  suppression: {record: {module: space, element: suppression}, sequenced: false}
  timeline: {record: {module: space, element: timeline}, sequenced: true, expireAfterWrite: 2678400000}
reads:
  - {name: awaiting, version: 1, params: {wait: text}, select: {from: instances, where: {contains: [awaits, {param: wait}]}, fields: [id, key, campaign], limit: 500}}
```

Durations are milliseconds. A read's `select` is an API-008 select document.

Each queue and table is a core Record with the same id as the object. Its
members are, in order, its system columns and then its declared fields.
Each member is a Field with the id `<object>.<field>`:

| API-008 type | Core Field | `umf.tables` native type |
|--------------|-----------|--------------------------|
| `text` | `scalarType: string` | `text` (`COLLATE "C"`) |
| `int` | `scalarType: integer`, `facets.integerWidth: {bits: 64, signed: true}` | `int8` |
| `float` | `scalarType: float` | `float8` |
| `bool` | `scalarType: boolean` | `boolean` |
| `timestamp` | `scalarType: timestamp` | `timestamptz` |
| `json` | `scalarType: json` | `jsonb` |
| `text_set` | `cardinality: set`, with `itemType` naming the required string Field `<object>.<field>.item` | `{kind: array, element: {kind: text}}` |

The other members of each Field:
- **Nullability.** Declared fields are `absent-allowed`, except table key
  fields, which are `required`. System columns are `required` exactly where
  the executor declares them `NOT NULL`.
- **States.** A queue's `state` Field lists its four states as
  `allowedValues`.
- **Merge rules.** A merge rule is a Field's `fireweed.space` payload:
  `{kind: field, merge: add_only | non_decreasing}`.
- **Keys.** A Record's primary Key is `id`. A table's key is its alternate
  Key `key`.

The `umf.tables` declaration is the executor's layout (API-008 §The
PostgreSQL executor):
- **Tables.** Each queue is the table `q_<name>`, with `fillfactor` 80.
  Each table is `t_<name>`.
- **Columns.** System columns keep their names, and declared fields are
  `f_<name>`. `id` is an identity column, generated by default.
- **Indexes.** The executor's indexes become `umf.tables` indexes:
  - a queue's unique index on `key`;
  - its claim index `(due_at, priority [DESC], id) WHERE state IN
    ('pending', 'leased')`;
  - its retention index on `finished_at`;
  - its sweep index `(state, due_at, attempts)`;
  - a table's expiry index on `expires_at`;
  - one index per indexed field: btree `(f_<field>, id)`, or GIN for a
    `text_set`.

  An index's `id` is `f_<field>` for a field index, and otherwise names
  its role. Index names are `<table>_<id>`, or a hash when that exceeds 63
  bytes.
- **Policy.** Row-level security denies people and allows the batch role
  every command. The executor connects as one service role, so that role
  is UMF's batch audience.

**Index choices are physical.** UMF keeps index choices out of the logical
Field, so a field's `index: true` comes from its `umf.tables` field index.
A table's first key field is indexed by the key's unique index. It loads
as indexed and has no index of its own.

## Loading

`load` makes three checks:
1. UMF validates the document, with `Semantics` as the host capabilities
   for `fireweed.space`. `Semantics` derives the `Schema` from the whole
   document and runs `fireweed_dsl::check::schema`. Without it, UMF reports
   the extension `SEMANTICS_UNCHECKED` and the document is refused as
   incomplete.
2. The derived `Schema` passes `fireweed_dsl::check::schema`.
3. The document equals `export` of that `Schema`, under the document's own
   ids. Only descriptive members may differ: `description`, `title`,
   `aliases` and `examples`. Any other difference is refused with
   `FIREWEED_NOT_CANONICAL` and the first differing JSON pointer.

The third check is what keeps the UMF declaration and the executor
together: a document's `umf.tables` declaration always describes the
tables the executor creates. A document can't choose other native types,
indexes or names, and can't add other extensions.

Problems are `{code, path, message}`. Codes:
- UMF's own codes, such as `EXTENSION_STRUCTURE` for an unknown
  `fireweed.space` member or `SET_ITEM_EQUALITY`;
- `FIREWEED_SCHEMA` for an API-008 check;
- `FIREWEED_NOT_CANONICAL`;
- `FIREWEED_SHAPE`, `FIREWEED_RECORD`, `FIREWEED_FIELD` and
  `FIREWEED_READ` for a document `derive` can't read.

## DDL

`deployment` compiles UMF's bundle with
`independentExtensions: [{id: fireweed.space, version: 0.1.0}]`: the
extension adds no tables, columns, constraints, indexes, policies or
grants. The configuration names:
- the PostgreSQL schema;
- an install owner;
- the person and batch roles (UMF CONTRACT-081 §Binding).

The executor's own DDL is written to match UMF's rendering:
- every text column uses `COLLATE "C"`;
- partial predicates are `state IN ('pending'::text COLLATE "C", …)` and
  `NOT (finished_at IS NULL)`.

So both produce the same catalog. A PostgreSQL 18 test
(`crates/fireweed-umf/tests/umf.rs`) applies both to the API-008 example,
the microsite example and a schema with every field type. It compares the
`q_`/`t_` tables' columns (type, nullability, collation, identity), index
definitions and uniqueness, and storage parameters. They must be equal. The
test also checks three things:
- the executor's claim query uses UMF's claim index;
- the batch role inserts through the identity column;
- a person can't insert.

UMF's DDL is stricter than the executor's in three ways:
- **Domain checks** (`umf_d_…`): timestamps within years 1 to 9999, the
  queue's state values, and a `text_set` holding a one-dimensional array
  without NULL items.
- **Row-level security**, and its grants.
- **Key constraints.** Keys are `UNIQUE`/`PRIMARY KEY` constraints rather
  than bare unique indexes, with the same indexes.

The executor still installs its own DDL, and it owns the space's internal
objects: `fw_requests`, `fw_queue_state`, `fw_sequences`, `fw_versions`, a
sequenced table's counter row, and the catalog functions. Installing a
space from UMF's bundle instead needs the executor to run as UMF's batch
role under row-level security; that is future work.

## Changes and versions

A space's documents change as its schema does (API-008 §Changing a
schema). `fireweed_dsl::check::change` decides which changes are allowed.
UMF's evolution check (CONTRACT-083) isn't required for that. An existing
table's `umf.tables` declaration changes only by appended columns, which
is what the executor allows.

`text_set` values are stored in UMF's canonical set order, ascending by
code point: `fireweed.text_set` sorts with `COLLATE "C"`.

## Dependencies

`fireweed-umf` depends on `umf-core` and `umf-codegen` by git revision,
because the UMF changes it needs aren't in a crates.io release yet:
- core `json` and `set`;
- `jsonb`, arrays, GIN and partial indexes;
- `float8`, `fillfactor` and identity columns on insert-allowed tables;
- building without `umf-core`'s embedded adapters.

Both are built with default features off. Fireweed needs none of the
JSON-LD and RDF adapters, and `deny.toml` rejects their dependencies.
